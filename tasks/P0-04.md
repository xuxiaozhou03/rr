# P0-04 验证 REA 服务可调用

> 执行边界：只执行本任务；不要读取整份清单，不要顺手执行下一任务。  
> 会话模式：新线程 / 单任务 / 可验收产物。  
> 输出上限：聊天总结不超过 30 行；命令输出只保留命中行或前 120 行。  
> 结束条件：本任务验收项全部满足，并写出 handoff 文件。

## 输入

- 本任务卡。
- 只按下方“操作”读取实际需要的最小文件。
- 禁止默认加载整份 `REA_COMPETITOR_REVERSE_ANALYSIS_CHECKLIST.md`。

## 任务正文

- 操作：

```bash
{
  echo "checked_at=$(date -Iseconds)"
  echo "target=$TARGET_URL"
  codex mcp list
} > "$EV/01-rea/mcp-status.txt"
```

- 然后在新的 Codex 会话中执行：

```text
1. 列出 REA MCP 的所有工具名称、描述和输入 schema；不要调用有副作用的工具。
2. 调用 REA 的只读 health/info 工具（若存在）。
3. 用目标 URL 做一次最小只读探测，输出请求、响应摘要和错误。
```

- 产物：
  - `evidence/01-rea/tools-list.json` 或等价文本
  - `evidence/01-rea/smoke-test.md`
- 验收：
  - [ ] 能看到实际工具名称和 schema。
  - [ ] 至少一个只读工具调用成功。
  - [ ] 失败时记录完整错误，不把“配置存在”误判为“可调用”。
- 阻塞规则：REA 不可用时，可继续执行不依赖 REA 的浏览器/静态分析任务，但必须标记 `REA 缺失`。

## 收尾要求

- 将完整证据写入任务正文指定的文件，不把大段原始输出粘贴到聊天。
- 创建 `handoff/P0-04.md`，仅包含：状态、产物路径、结论、阻塞、下一任务建议。
- 未满足验收时标记 `blocked`，不要继续下一任务。
