# P2-03 建立状态流转模型

> 执行边界：只执行本任务；不要读取整份清单，不要顺手执行下一任务。  
> 会话模式：新线程 / 单任务 / 可验收产物。  
> 输出上限：聊天总结不超过 30 行；命令输出只保留命中行或前 120 行。  
> 结束条件：本任务验收项全部满足，并写出 handoff 文件。

## 输入

- 本任务卡。
- 只按下方“操作”读取实际需要的最小文件。
- 禁止默认加载整份 `REA_COMPETITOR_REVERSE_ANALYSIS_CHECKLIST.md`。

## 任务正文

- 操作：记录状态机，至少包括：
  - `idle → loading → ready → interacting → error`
  - 资源加载失败与重试。
  - WebGL 不可用或 context lost。
  - 登录过期或权限不足。
- 产物：
  - `evidence/03-ux/state/state-transition.md`
  - `evidence/03-ux/state/state-examples.json`
- 验收：
  - [ ] 状态之间的事件和条件明确。
  - [ ] 有进入和退出每个状态的证据。
  - [ ] 不把推测状态当作已证实状态。

## 收尾要求

- 将完整证据写入任务正文指定的文件，不把大段原始输出粘贴到聊天。
- 创建 `handoff/P2-03.md`，仅包含：状态、产物路径、结论、阻塞、下一任务建议。
- 未满足验收时标记 `blocked`，不要继续下一任务。
